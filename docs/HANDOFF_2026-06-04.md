### 3. Lane following (bird's-eye) — working
- `config/lane_params.json` drives the warp + sliding-window line tracker.
  Started from tilt-aligned defaults; `eval_y_pct` lowered to **72** (more
  lookahead → smoother). Tested on the robot: straights perfect (conf 1.0,
  off≈0), curves followed with auto-slowdown; sharp curves drop conf to ~0.75 and
  fill to ~6-7% (line exits the trapezoid side) but it doesn't lose the line.

### 4. Controller (PD) — the key tuning finding
- Gains are live-tunable ROS params (`kp`,`kd`,`max_v`,`max_w`,`curve_slow_gain`,
  `curve_min_scale`), persisted in **`config/control_params.json`** (loaded at
  startup as defaults).
- **KEY RESULT: this robot oscillates with derivative on.** kp high diverged;
  raising kd made it *more abrupt* (D amplifies noise/latency). What works:
  **kd = 0 (pure P), kp = 0.0018, eval_y_pct = 72 → straight and stable.**
  Current `control_params.json`: kp 0.0018, kd 0.0, max_v 0.08, max_w 0.6,
  curve_slow_gain 0.6, curve_min_scale 0.4.

### 5. Live tuning + control system (the "pro" UX)
- **`tools/param_tuner.py`** (`scripts/run_param_tuner_jetson.sh`): curses TUI run
  on the Jetson over `ssh -t`. Sets params live via the raw
  `/autonomous_racer/set_parameters` service (NOT AsyncParameterClient — too old
  on the Jetson). Subscribes `/lane_status` for live metrics. Keys: `j/k` select,
  `-/=` nudge, `s` save (publishes `/save_params`), `d` drive on/off, `1/2/3`
  left/straight/right, `0` reset intersection, `r` toggle recorder, `q` quit.
  Drive/intersection/recorder publish from this running node → instant (the
  `set_*.sh` scripts pay ~1-2 s DDS discovery each call).
- `scripts/run_param_gui_jetson.sh`: rqt_reconfigure via `ssh -X` (alt GUI).
- `scripts/set_gain_jetson.sh` / `set_intersection_jetson.sh` / `set_drive_jetson.sh`:
  one-shot CLI equivalents.
- All `LaneParams` fields exposed as live params `lane.<field>`; on-set updates
  `self.lane_params` and invalidates the cached homography.

### 6. HUD / states / quiet logs
- Video HUD (top bar) is the **state display**: STATE (FOLLOW/APPROACH/WAIT/
  COMMIT/RECOVER/HOLD), drive, light, BEV off/conf/curv, v/w, gains, `REC n`.
- `verbose` param (default False) → sets logger to WARN, killing per-frame
  `[VISION]/[MATH]/[LANE]/[TRACKING]` spam. `-p verbose:=true` to debug.
- `/lane_status` (Float32MultiArray `[off,conf,curv,v,w]`) for tuner / PlotJuggler
  / Foxglove.

### 7. Recorder
- `/recorder_enable` (Bool) → saves the annotated frame every `snapshot_interval`
  (2 s) to Jetson `debug_dataset/follower_session/`, filename
  `follow_<ts>_<STATE>.jpg`. Tuner `r` toggles. Pull with
  `scripts/pull_follower_snapshots.sh` → `datasets/follower_session/`.

### 8. Intersections
- State machine: detect zebra → `APPROACH` (creep, follow line) → arrives when
  entry zebra is close (`approach_target_entry_y_pct=82`) AND centered → `WAIT`
  (stops, prompts) → operator decision (`1/2/3` or `/intersection_decision`) →
  `COMMIT` turn → back to FOLLOW. `/intersection_reset` (tuner `0`) clears it.
- **False positives:** the puzzle-piece floor seams look like zebra dashes →
  spurious intersection on straights. Proposed but NOT built: an
  `enable_intersections` param to disable detection while tuning line following.

## Gotchas resolved (so they aren't reintroduced)
- **Config path bug:** node loads/saves config via `_find_config` /
  `_config_save_path`, which look in the **source tree**
  (`/home/puzzlebot/ros2_ws/src/puzzlebot_ros/config`), not relative to the
  installed `__file__` (which resolves to `site-packages/config`, nonexistent).
  This was why `control_params.json` silently didn't load (kp stuck at 0.003).
- **`ssh -X -t` closed the node instantly.** Fixed: plain `ssh -X` + a `trap`
  that pkills the remote follower on exit (Ctrl-C cleans up) + a pre-launch pkill.
- **AsyncParameterClient missing** on the Jetson's rclpy → tuner uses raw
  Set/GetParameters services.
- **Camera BUSY / multiple instances:** relaunching without stopping orphaned
  `line_follower` processes (5 piled up) that fought over the CSI camera; symptoms
  were erratic motion + false intersection. `stop_demo.sh` clears; the run script
  now self-cleans.
